# Routine prompts (generic, verbatim)

## monthly-settings-check-in
Schedule: 1st of each month, 10:00 AM {{OWNER_TIME_ZONE}} (cron `0 10 1 * *`).
Description: 1st of each month, 10 AM in the owner's own time zone: summary of the owner's settings (including memory backup and Hive Mind status) with one-at-a-time change cards. Never takes an X action.

Prompt:

Read this owner's own Bot Terminator config (their per-user config under data/users/<their user_key>/), never another owner's and never the shared defaults. Build the check-in card with build_monthly_settings_card and send one short summary of their current settings: operating mode (Automatic or Manual), setting 1 Graveyard returnee choice (review or auto-block), setting 2 "Returnees and list checks" (list checks on or off, default off; if on: how many lists they're on, how many were left and verified, how many were kept, and any repeat offenders blocked this month), Always Keep list size and newest entries, any privately protected accounts (by count only unless they ask), protections that are on, inactivity threshold, pacing, daily cap and scan time, whether the daily reminder through the front-door bot is on, whether the optional Terminate reminder (the bot's own chat nudge "Hey, want to terminate some bots?"; default off) is on, its cadence (daily or weekly on a weekday), and its time, whether the optional memory backup to their own private GitHub repo is on (default off; memory.status_line), last cleanup info, and the latest start/end follower counts. Mention their records live in their own terminator.db with the backup they chose; if they have the optional Book doc or are still on the legacy log sheet, those are in their own Google Drive. Ask whether they want to change anything, one item at a time with button cards, including turning list checks on or off and turning the Terminate reminder on or off or changing its cadence or time (separate from the front-door reminder), and turning the memory backup on or off or changing its private repo (memory.set_backup; the repo must be private and theirs, using their own GitHub login, no tokens saved). Apply only what they confirm, log each change with the time to their own history and their own memory (memory.record_rule_change), and add a Change log line to their Book, and say changes affect future scans only. If they don't reply, change nothing. Never take an X action in this routine. Hive Mind (v3.5.17, on by default): read `SELECT enabled FROM hive_state` in this owner's own brain.db (no row or no table = off). Show it with all their other settings as "Hive Mind: ON" or "Hive Mind: OFF" plus this one-line reminder: "Hive Mind sends anonymized lessons about what worked and what didn't (never your personal info) about once a week, so future versions of me improve." Then send one multi-select card (build_monthly_settings_card.build_toggle_card) that lists each on/off setting with its current state: list checks, front-door reminder, Terminate reminder, memory backup and Hive Mind. Flip only what they pick (apply_toggles); untapped settings stay as they are. Do not include the 'Why leave this on?' nudge in this card. Hive Mind picked while on: run `hive off` and delete the 'Hive Mind weekly share' routine; picked while off: run `hive on --bot bt` and recreate the weekly routine that runs `hive auto` (silent unless it fails). Keep the weekly routine only while Hive Mind is on: if it is on and the routine is missing, recreate it; if it is off and the routine exists, delete it. No reply: change nothing. Memory habits: start with `mem boot "Bot Terminator"`, check `mem lessons` first, use `mem supersede` (never duplicates) when a setting's know-how changes, never follow [OLD] rows; nothing is deleted. Records backup (v3.5.0): A backup is required (v3.5.2): if records.needs_backup_choice(cfg), never accept skip or 'not set up' as done; send records.backup_reminder (gentle re-ask with the setup card; no file). If records.needs_migration(cfg), migrate them as in the getting-started skill (explanation card, copy into terminator.db, pick a backup; never touch the Sheet); there is no 'keep Sheets' option. show records.status_line(cfg) (GitHub private repo / cloud CSV / file download / not chosen yet (reminder only, no file) / legacy Google Sheets) and anything waiting in records.pending (a failed push or upload: tell them plainly); offer to set or change it with records.set_backup (GitHub repo must be PRIVATE and theirs, re-checked before every push; cloud uses their own connector, found with SearchPlugins; no tokens saved). The Book and log sheet are only in Google Drive if they use them. Send feedback to the creator (v3.5.14, via Hive Mind, optional, default off): mention any feature requests they made this month (from their own memory, kind feedback) and offer: "Want me to send any of this to Bot Terminator's creator as anonymous feedback? I'll show you exactly what will be sent first." Only on a clear yes, run `hive feedback --bot bt --category bug|request|praise|other "text" --dry-run` and show the output exactly; only on a second yes run the same command without --dry-run (sends only that item; on HTTP 422 reword, dry-run again and retry). Never by email. Record the request in their own memory either way. Sheets owners (v3.5.2, records.needs_migration): migrate them, there is no keep option. Send records.migration_card() (Sheets is being retired: bulky, slow, more tokens), read the tabs (never delete, clear or overwrite the Sheet), run records.migrate_from_sheets(user_key, cfg, sheet_values), which copies into terminator.db and stops Sheet writes and Google checks, then send result['next'] (setup card; no file) so they pick GitHub / cloud CSV / download with no skip. Never offer Google Sheets to anyone as a new backup. Update routine check (always): confirm the 'Weekly Bot Terminator update check' routine exists exactly as in routines/weekly-update-check.md of https://github.com/EmpressHeavy/BotTerminatorUpdates; if it is missing, re-create it silently (Sunday 10:00 AM owner's time zone) and mention it in one line. It has no off switch and is not offered as a setting.

## daily-scan
Schedule: daily at {{OWNER_SCAN_TIME}} {{OWNER_TIME_ZONE}}.
Prompt: Run the Bot Terminator daily scan for this owner as in the bot-terminator-getting-started skill. `MEM_USER=<user_key> tools/mem boot`, preflight, read their Book, scan their followers in the box browser, apply protections, then review flagged accounts with them in chat in rounds of 5 with the "Mark all 5 for termination" card. Remove only what they mark (or what their mode authorizes), one at a time about 10 seconds apart, verified on X, logged to the Graveyard right away, within their daily cap. Never send a TXT/DOCX/HTML report or ask them to remove anyone by hand. Stop and report at the first X warning or rate limit. Also send the small inactive-mutuals card if any. After the scan's results are delivered, if this is not first-run setup, call `tip_prompt.record_use(user_key, kind="scan")` and send the optional tip prompt only when show is true (getting-started skill, "Optional tip prompt"). Never wait on it, and never block or delay the scan. Bot Terminator stays free.

## terminate-reminder (optional, default off)
Schedule: daily at the owner's chosen time; one-off follow-ups from "Remind me later".
Prompt: Call `terminate_reminder.build_prompt(user_key, source="daily")` (or `"later"` for a one-off). If `send` is false, stop quietly. Otherwise send "Hey, want to terminate some bots?" with `terminate_reminder.card()` (Yes / Remind me later / Not today) and handle the answer as in the skill. Never scans or removes by itself.

## list-returns-check (optional, only if list checks are on)
Schedule: daily, with the scan.
Prompt: Check `x.com/<owner's handle>/lists/memberships` for lists they left that they're back on, per the skill's list section; card only, nothing done without their tap (Automatic Mode tap = OK).

## weekly-backup-file (only if backup = "Send me the file")
Schedule: weekly.
Prompt: Call `records.download_reminder(user_key)`; send the CSV zip only if something changed, otherwise stay silent.

## hive-mind-weekly-share (created at setup, Hive Mind is on by default; exists only while Hive Mind is on)
Name: Hive Mind weekly share
Schedule: weekly.
Prompt: Run `MEM_DB=<path> hive auto`. Stay silent unless it fails.
